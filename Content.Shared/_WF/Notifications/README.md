# Notifications

Which events flash the game window and play an alert sound, under Game Options > Misc > Notifications. The two flashes
that already existed stay on by default; the new alerts start off:

| Setting | Default | Event |
|---|---|---|
| `wf.window_flash_round_start` | on | the server's window attention request when the round starts |
| `wf.window_flash_ahelp` | on | an incoming admin message |
| `wf.window_flash_highlight`, `wf.chat_highlight_sound` | off | a chat message matching one of the player's highlights |
| `wf.window_flash_ghost_role`, `wf.ghost_role_sound` | off | the open ghost role count going up while a ghost |

Highlight alerts skip the player's own messages and fire at most once every two seconds. The cloning, return-to-body,
cryosleep and Wolfmed prompts still always flash the window, because each waits for the player's answer.

Entry points: `WFWindowFlash.Request`, which the round start and ahelp paths call by marked edits;
`ChatUIController.WfOnHighlights`, called after highlighting in `ProcessChatMessage`; and `WFGhostRoleAlertSystem`,
which listens to `GhostSystem.GhostRoleCountUpdated`.
