# PixelShift

SS13-style pixel shifting. Hold **Pixel shift** (`WFPixelShift`) and tap movement keys to nudge your own sprite a pixel
at a time; hold **Tilt sprite** (`WFPixelTilt`) and tap left or right to lean it 5 degrees at a time. **Reset pixel
shift and tilt** (`WFPixelShiftReset`) puts it back. All three start unbound, sit under Movement on the Controls tab,
and aren't in the SS13 preset. The shift stays until reset: walking doesn't clear it.

Limits are server cvars: `wf.pixel_shift_max_offset` (16 px per axis, half a tile) and `wf.pixel_shift_max_tilt`
(45 degrees). Restrained, stunned, critical, dead or asleep mobs can't adjust it (`ActionBlockerSystem.CanInteract`).

`WFPixelShiftComponent` holds the shift and is networked, so everyone sees it. The server adds it on the first tap;
`SharedMoverController.WfTryPixelShift`, from a marked edit in `HandleDirChange`, hands key presses to
`WFPixelShiftSystem.TryNudge`. On the client `WFPixelShiftVisualsSystem` adds the shift and tilt after animations
run and `WFPixelShiftRestoreSystem` takes them off before the next frame, the same pattern as Waddle, so lunges,
jitter and the lying-down rotation still play from the mob's own base. The tilt is left out while the mob is down or
buckled, so it never fights the lying-down rotation. A marked edit in `JitteringSystem` keeps the shift out of the
base offset jitter returns to.
